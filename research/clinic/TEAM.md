# 治療院データ集め：チームの作業ルール

このファイルを読んだ Claude Code は、ここに書いた手順とルールに従って、人に聞かずに最後まで進めてください。
人に聞くのは「止まって報告する」と書いた場面だけです。

始め方（人がやること）：このフォルダで Claude Code を開き、次のように伝える。

> research/clinic/TEAM.md を読んで、リーダーとして最後まで進めて

---

## 0. 前提（必ず先に読む）

- ページはもうできている：`routes/clinic.js`、`views/clinic/`、`public/css/clinic.css`、`scripts/build-clinic-data.js`。
  **やることはデータ集めだけ。** ページの見た目や仕組みは変えない（下の「直してよいもの」以外）。
- サイトが読むデータ：`data/clinic/clinics.json`。これは `npm run clinic:build` で
  `research/clinic/clinic-data.csv` から作る。JSON を手で書き換えない。
- 列の書き方・決まった言葉・集める基準は `research/clinic/依頼文.md` の「ここから〜ここまで」が正本。
  このファイルと食い違ったら、依頼文.md に従う。
- 対象：東京23区と神奈川県。種類は 整骨院・接骨院／鍼灸院／整体・コンディショニング／スポーツ整形外科。
- 目標：40院（23区 25院・神奈川 15院くらい）。4つの種類のどれも、少なくとも5院は入れる。

## 1. 絶対に守るルール

1. **実在を確かめた院だけを載せる。** その院の公式ページを実際に開き（WebFetch）、院名・住所・電話番号を見て確かめた院だけを入れる。
   検索結果のまとめ文や記憶だけで行を作らない。開けなかった院は入れない。
2. **書くのは公式ページに書いてある事実だけ。** 推測で埋めない。わからない欄は空欄にする。
3. 口コミサイト・ランキングサイト・予約ポータルの評価や感想は使わない（院を見つける手がかりにするのはよいが、事実は公式ページで確かめる）。
4. 「院の紹介」に「治る」「効く」「改善」「根本から」「No.1」「実績◯人」などの効果・実績・比べる言葉を入れない。体験談も入れない。
5. 点数・順位・おすすめはつけない。ページの仕組みも変えない。
6. フォーム（`/clinic/apply`）からテスト送信しない。本番の Firebase に入ってしまう。
7. 秘密情報（`.env`、`firebase/serviceAccountKey.json`）は開かない・コミットしない。
8. 同じファイルを2人で同時に書かない（下の分担を守る）。

## 2. 役割と分担

チーム（またはサブエージェント）を作れない場合は、リーダーが同じ手順を1つずつ順に行う。

| 役割 | 担当 | 書いてよいファイル |
|---|---|---|
| リーダー | 分担・統合・ビルド・表示確認・報告 | `research/clinic/clinic-data.csv`、`research/clinic/report.md`、`public/sitemap.xml`、`public/sitemap.txt` |
| 調べ係A | 23区のうち 千代田・中央・港・新宿・文京・台東・墨田・江東・品川・目黒・大田（13院くらい） | `research/clinic/parts/a.csv` |
| 調べ係B | 23区のうち 世田谷・渋谷・中野・杉並・豊島・北・荒川・板橋・練馬・足立・葛飾・江戸川（12院くらい） | `research/clinic/parts/b.csv` |
| 調べ係C | 神奈川：横浜市・川崎市（10院くらい） | `research/clinic/parts/c.csv` |
| 調べ係D | 神奈川：それ以外（相模原・藤沢・湘南・横須賀など。5院くらい） | `research/clinic/parts/d.csv` |
| 確認係 | 調べ係が出した全行を、もう一度公式ページで確かめる | `research/clinic/parts/check.md` |

- 調べ係は、`research/clinic/clinic-data.csv` の1行目（見出し）をそのまま写した CSV を作り、1院1行で書く。文字コードは UTF-8。
- 院IDは `院名のローマ字-区市名` の形で、半角英小文字・数字・ハイフンだけにする（例 `abc-seikotsuin-shibuya`）。ほかの係とかぶらないよう、最後に担当の区市名を必ず入れる。
- 種類の偏りを防ぐため、調べ係は自分の担当の中で、4つの種類がなるべく全部入るように選ぶ。
- 同じチェーンは全体で3院まで。かぶったらリーダーが削る。

## 3. 手順

### ステップ1：準備（リーダー）
- `git status` で作業前の状態を見る。`routes/clinic.js` などがまだコミットされていなければ、
  **データとは別に** 先に「治療院ページを追加」としてコミットする（push はしない）。
- `research/clinic/parts/` を作る。

### ステップ2：調べる（調べ係A〜D、同時に進めてよい）
- 依頼文.md の基準で院を探し、公式ページを開いて1行ずつ埋める。
- 「確認日」は調べた日、「掲載の経緯」は「公開情報」、「出典URL」は実際に開いて確かめたページ。
- 迷ったこと・確かめられなかったことは「備考」に書く。

### ステップ3：確かめる（確認係）
調べ係の全行について、出典URLを自分で開き直して次を確かめ、`check.md` に1院1行で「OK／直した／外すべき」と理由を書く。
- 院名・住所・電話が公式ページと同じか。閉院・移転・休業の告知がないか。
- 土日・19時以降の受付が、営業時間の表記と合っているか。
- 資格・部位・設備が、公式ページに本当に書いてあるか（書いていないものは消す）。
- 「院の紹介」にルール4の言葉がないか。100字以内か。
- 間違いは parts の CSV を直接直してよい（確認係はこのときだけ parts/*.csv を書いてよい）。

### ステップ4：まとめる（リーダー）
- parts の4つを1つにして `research/clinic/clinic-data.csv` に書く（見出しは1回だけ）。check.md で「外すべき」の院は入れない。
- 院IDと院名の重複、同じチェーン4院以上を消す。
- `npm run clinic:build` を実行する。**「注意:」が0件になるまで** CSV を直して実行し直す。
- 件数と種類ごとの内訳が目標に足りなければ、足りない分だけステップ2〜3をもう一度回す（最大2回まで）。

### ステップ5：表示を確かめる（リーダー）
- `.claude/launch.json` の `start-3200` でローカルを起動し、次を見る：
  - `/clinic` に全院が出て、`<meta name="robots" content="noindex">` が**消えている**。
  - 種類・部位・土日・市区町村の絞り込みで、件数が変わる。
  - 院ページを5つ選んで開き、エラーや空欄だらけになっていない。
- 終わったらサーバーを止める。

### ステップ6：サイトマップ（リーダー）
- `public/sitemap.xml` に `/clinic`、`/clinic/about`、各院 `/clinic/<院ID>` を足す。
  形はプロテインと同じ（`https://runnersplac.onrender.com/...`、`<priority>0.8</priority>`）。
- `public/sitemap.txt` にも同じページを足す（こちらは `https://runnersplac.com/...`）。
- `/clinic/apply` は足さない。

### ステップ7：コミットして報告（リーダー）
- データ・サイトマップを「治療院◯院のデータを追加」としてコミットする。
- `research/clinic/report.md` に次を書く：院数と種類・地域ごとの内訳、外した院とその理由、確かめきれなかったこと、ビルドの結果。
- **ここで止まって報告する。push はしない。**
  人が report.md と数院を見てOKを出したら、`git push origin main` して、本番 `https://runnersplac.onrender.com/clinic` で表示を確かめる。

## 4. 直してよいもの・止まって報告すること

直してよい（直したら report.md に書く）：
- ページの明らかな不具合（表示崩れ、エラーで開けない）を、最小限の変更で直す。
- `scripts/build-clinic-data.js` の決まった言葉の一覧には**足さない**。合わない値は CSV 側を決まった言葉に寄せるか、空欄にする。

止まって報告する：
- 40院の半分（20院）も、確かめられた院が集まらないとき。
- ページの仕組みや決まった言葉を変えないと進めないとき。
- 秘密情報や本番のデータベースに触る必要が出たとき。
- このファイルのルールと依頼文.md で、どちらにも書いていない判断が必要になったとき。

## 5. 今後の更新（2回目以降）

- 院を足すとき：同じ手順で parts に書き、clinic-data.csv の後ろに足す。今ある行は消さない。
- 院から申込が来たとき（Firebase の `clinicApplications`、status が「未対応」のもの）：中身を公式ページで確かめてから CSV に反映し、「掲載の経緯」を「院からの申込」にする。Firebase の status の書き換えは人がやる。
- 半年に1回、全院の出典URLを開き直して、閉院・移転・営業時間の変更を確かめる。
